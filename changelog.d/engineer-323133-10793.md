### Fixed

- A scheduler runner whose Redis refuses its credential, a refused login or an ACL denial, now prints `scheduler stops: the state store refused its credential (<error>: <text>)` and exits 4 on that pass in any swarm, instead of logging that the state store did not answer and retrying every second forever. Its supervisor starts no new runner and exits 4, and the `agentihooks-scheduler` user unit no longer restarts a supervisor that exits 4. A timeout or a dropped connection still gets a new pass every second.

### Changed

- A scheduler supervisor that stops because its proof swarm runner's state store did not answer for 300 seconds now exits 3, its runner's code, instead of 0.
