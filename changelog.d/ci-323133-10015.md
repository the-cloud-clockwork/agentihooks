### Fixed

- The Semgrep workflow sets `EIO_BACKEND: posix` for all its jobs, so semgrep-core runs on the Eio posix backend instead of io_uring. Since Linux 6.14 the kernel counts each io_uring ring and registered buffer against the user's locked memory, and the self hosted runner containers run as uid 1001 with an 8 MiB limit, so the scan and feature-tests jobs failed at random with `Cannot allocate memory io_uring_queue_init`.
