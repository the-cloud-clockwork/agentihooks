Swarm git calls retry once over https when GitHub refuses ssh auth. `scripts.swarm.git_https.run` reruns a call that failed with `Permission denied (publickey` with `url.https://github.com/.insteadOf` and the gh credential helper set through `GIT_CONFIG_COUNT` entries for that call only, so `swarm publish` pushes, fetches and ls-remote, the `stack.shell` fetch paths used by park, ready and restack, and the `swarm branch` origin check keep working while ssh is refused. No token enters argv, the environment or the output. The worktree script runs again with the same settings when a fetch inside it is refused, since each of its fetches stops before it creates or removes a worktree. A refused stack fetch can still fall through to the existing anonymous https fetch, a third attempt.
