### Fixed

- The ledger server writes its process id file only once its hub projector is
  running, just before it serves requests, so the pid file never names a server
  whose projector has not started or failed to start. Accepted trade off: the
  startup window with no pid file, which already spanned the listener bind and
  the thread starts, now also spans the projector start. A `--stop` in that
  window reports no server pid file and leaves the starting server holding its
  port, and a `--reload` sends no hangup and only ensures a server runs.
