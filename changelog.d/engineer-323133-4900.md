### Added

- Per record fencing keys: once a swarm is migrated with `python -m scripts.swarm.records_migration <slug> --writers-upgraded`, every fenced write sends only the records it changed through one Lua script that checks the lease owner, epoch and expiry and the revision of every record the change read or wrote, then writes all of them or none, and appends one entry to a capped fence log stream. One agent change on a copy of the live swarm drops from 2,013,213 to 6,758 bytes sent to Redis.
- The records port keeps the whole fencing document behind the same interface for bus deployments and swarms not yet migrated; readers use records once a swarm is migrated and the document otherwise, and the migration rewrites the document in the same transaction so a write that read it before the move retries onto the records.
- Archive rows are revision checked when the change hydrated the archive; a row put without hydrating is written without a check, and a change that scans a whole section checks the records that existed when it read them.
