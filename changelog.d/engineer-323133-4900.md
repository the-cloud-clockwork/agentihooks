### Added

- Per record fencing keys: once a swarm is migrated with `python -m scripts.swarm.records_migration <slug> --writers-upgraded`, every fenced write sends only the records it changed through one Lua script. The script checks the lease owner, epoch and expiry, and the revision of every record the change wrote and every current record it read (archive history excepted). It then writes all of them or none and appends one entry to a capped fence log stream. On a copy of the live swarm's fencing document, the task's byte measurement script counted 2,013,213 bytes sent to Redis for one agent change on the document path and 6,758 on the records path.
- The records port keeps the whole fencing document behind the same interface for bus deployments and swarms not yet migrated. Readers use records once a swarm is migrated and the document otherwise. The migration rewrites the document in the same transaction, so a write that read the document before the move retries onto the records.
- Archive rows are revision checked when the change hydrated the archive, and a row put without hydrating is written without a check. A change that scans a whole section checks every record that existed when it read them, so a scan's batch grows with the section.
