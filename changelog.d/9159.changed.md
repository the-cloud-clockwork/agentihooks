Swarm modules no longer gain direct `gh` commands: the Semgrep rule `swarm-source-control-port` refuses a `["gh", ...]` command under `scripts/swarm` outside the files listed in `.semgrep/source-control-allowlist.json`, and the scan fails when that list grows against the caller base. `swarm park` reads whether a dependency pull request merged into dev, and `swarm publish` reads whether a predecessor pull request is settled, through the source control port and its sixty second deadline.
The `swarm-source-control-port` rule now also refuses the GitHub adapter's command builder, `scripts.tick.adapters.github.command`, outside the adapter; every swarm caller builds its `gh` command through it, so each file still doing so stays on the shrink only exception list until its calls move onto port tools. `swarm publish` reads a merged pull request branch, the panic button reads a fix branch, and the swarm health checks read check runs through the source control port, whose change record now names the head branch. The feature map carries `swarm-tick-source-control-port`.
