### Added

- When a hive starts draining, through the tick hive sweep, `agentihooks hive remove`, the hive stop drain or `agentihooks hive set <id> draining=yes`, the master seat of each swarm with a live agent on that hive now gets one inbox item naming the hive, the drain reason and that swarm's agents. When the hub finds a hive lost and ends its executions, the master of each swarm it ran gets one item naming the hive, the reason, the executions and the agents. Each item is sent once per hive and drain or loss, so a repeat drain of a draining hive sends nothing. A process that talks Redis as a hive member, such as a worker pod's stop drain, sends none, because the inbox relay refuses its items. The agent hand off orders and the hub loss log line are unchanged.
