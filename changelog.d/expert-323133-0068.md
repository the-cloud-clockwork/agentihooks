### Fixed

- A CI lab worker starts on a work root that belongs to another user. Emptying the work root at start changed the mode of every folder it entered, the root included; in the lab pod that root is an `emptyDir` owned by root with mode 777 and the worker runs as user 1001 with every capability dropped, so the system refused the mode change and the worker crash looped. A folder's mode is now changed only when it lacks an owner bit. The lab image smoke starts the worker as the lab chart runs it, on a full work root owned by root, and refuses an image whose worker does not reach its first lease call, leaves a planted entry in its root or does not exit 0 on SIGTERM.
