### Changed

- The ledger repository is built once per process by the `scripts.swarm_ledger.storage`
  composition root, the only module outside the store that names its SQLite
  implementation. The repository package binds no global repository, and an import
  check refuses any other production module under scripts or hooks importing the
  SQLite store. Hooks keep their read only ledger reads, now taken from the
  composition root, because a hook process reads a few keys and exits.
- The repository interface gains transactions, read snapshots and relay journal
  operations. Hierarchy backfill and the hosted migration use them instead of opening
  SQLite connections and the core lock themselves.
- The ledger server keeps unrelayed revisions in the ledger database's relay journal
  instead of `ledger-unrelayed.json`, and moves a journal file left by an older server
  into the database at start.
